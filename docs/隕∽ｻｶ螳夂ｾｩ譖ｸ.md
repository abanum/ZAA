# NTSC 無信号砂嵐シミュレータ 要件定義書

| 項目 | 内容 |
|---|---|
| 名称 | NTSC Snow Simulator |
| 版 | 1.0 |
| 対象環境 | WebGL2 + WebAudio 対応ブラウザ（Chrome / Edge / Firefox / Safari 16 以降） |
| 実装言語 | JavaScript (ES2020, ES Modules) + GLSL ES 3.00 |

---

## 1. 目的

NTSC-M 方式の受像機が無信号（NO SIGNAL）状態に置かれたときに現れる「砂嵐」を、
乱数テクスチャの貼り付けではなく **受信機の信号処理系をモデル化して** 再現する。

単純な一様乱数ノイズと実機の砂嵐は、以下の点で見た目が明確に異なる。
本ソフトはこの差分をすべて信号処理として実装することを目的とする。

| 観点 | 単純乱数 | 実機 |
|---|---|---|
| 輝度分布 | 一様 / 正規 | **レイリー分布**（包絡線検波の結果） |
| 明暗の向き | 対称 | **負変調**のため振幅大 = 暗 |
| 粒の形 | 正方形 | 映像 LPF により **横長** |
| 色 | 付かない or 全面カラー | **カラーキラー**によりモノクロ |
| 時間変化 | フレーム単位 | **フィールド単位 59.94Hz・奇偶走査線が交互** |
| 輪郭 | ドット状 | ビームスポット径と蛍光体残光でにじむ |

---

## 2. 適用範囲

### 2.1 対象とするもの
- チューナ／IF 段の熱雑音（複素ガウス雑音）
- 映像検波（包絡線検波）と AGC
- 負変調（NTSC-M）の映像レベル変換
- 映像 LPF（輝度帯域制限）
- 3.58MHz 色副搬送波帯の同期検波と I/Q → RGB 変換
- カラーキラー、局部発振のフリーラン位相ドリフト
- インターレース走査、ビームスポット、蛍光体残光、走査線、画面曲率
- FM 音声の無信号雑音（三角雑音 + 75µs デエンファシス）

### 2.2 対象外
- 同期分離回路の挙動（画面のローリング／垂直同期外れ）
- 3 次元 Y/C 分離、コムフィルタ
- 実際の RF 受信、チャンネル選局、映像入力
- PAL / SECAM 方式

## 4. 信号処理仕様

### 4.1 サンプリンググリッド

デジタルコンポジットの標準である **4fsc サンプリング**を用いる。

```
fsc = 3.579545 MHz
fs  = 4 × fsc = 14.31818 MHz
1H  = 63.5555 µs → 910 サンプル（有効映像 52.6µs ≒ 754 サンプル）
1 フィールド = 262.5 走査線（有効 243 走査線）
```

副搬送波の位相が 1 サンプルあたり π/2 ずつ進むため、色の同期検波が
乗算テーブルなしで実装できるという利点がある。

### 4.2 Pass 0 — 雑音生成（NoiseFragment）

ハッシュ関数 + Box-Muller により複素ガウス白色雑音 `I[n], Q[n]` を生成し、
RGBA8 テクスチャの R,G へ `[-4σ, +4σ] → [0,1]` で線形写像して格納する。
ハッシュの入力は `(走査線番号, サンプル番号, フィールドシード)` とする。

検波パスの FIR タップごとに Box-Muller を呼ぶと 1 サンプルあたり 13 回の
log/sqrt/sin/cos が発生するため、独立したパスとして 1 回だけ生成する。
8bit 量子化による誤差は FIR 通過後で RMS 0.004（表示 8bit の 1 階調程度）であり、
統計量（平均・標準偏差）は小数点以下 4 桁まで一致することを確認済み。

### 4.3 Pass 1 — 検波（DetectorFragment）

1. Pass 0 の雑音テクスチャを `texelFetch` で読み出す。走査線の端は巻き戻して参照する。
2. IF 帯域幅 B に相当する FIR ローパス（ハミング窓、13 タップ）を
   I/Q それぞれに適用する。複素包絡線表現のためカットオフは **B/2** とする。
3. フィルタ後に分散を 1 に正規化する。
4. 包絡線検波を行う。

   ```
   env[n] = sqrt(I[n]² + Q[n]²)    → レイリー分布（σ=1, 平均 √(π/2)=1.2533）
   ```
5. AGC は無信号時に最大利得へ張り付き、緩やかにハンチングする。
   走査線ごとに微小な利得変動 `wobble` を与える。
6. **負変調**を適用する。搬送波振幅が大きいほど暗い。

   ```
   video[n] = clamp(1 − env[n] × (level / 1.2533) × wobble, 0, 1)
   ```

### 4.4 Pass 2 — デコード（DecoderFragment）

**輝度**

映像帯域 `f_luma`（既定 3.6MHz）の窓関数法 FIR（17 タップ）を水平方向に適用する。
この帯域幅が水平方向の相関長を決め、砂嵐の粒の横幅を支配する。

```
独立成分数 ≒ 2 × f_luma × 52.6µs
  4.2MHz → 約 440 個 / 走査線
  3.6MHz → 約 380 個 / 走査線
```

有効走査線 486 本に対して水平方向がこの程度であるため、
粒は **わずかに横長** になる。

**色**

```
ph[n] = (π/2)·n + φ            ← 4fsc サンプリングにおける副搬送波位相
I = 2·LPF{ video[n]·cos(ph[n]) }
Q = 2·LPF{ video[n]·sin(ph[n]) }   （復調後 LPF: 0.6MHz, 25 タップ）
```

カラーバーストが存在しないため局部発振はフリーランし、位相 φ は
`chromaDrift [rad/s]` の速度でゆっくり回転する。結果として色斑の色相が変化する。

**カラーキラー**

バーストが検出できないため通常はキラーが作動し、クロマゲインを 0 にする。
これにより砂嵐はモノクロとなる。キラーを OFF にした場合のみ色が現れる。

**RGB 変換**

```
R = Y + 0.9563·I + 0.6210·Q
G = Y − 0.2721·I − 0.6474·Q
B = Y − 1.1070·I + 1.7046·Q
```

### 4.5 Pass 3 — CRT 表示（DisplayFragment）

- 2 レイヤーのテクスチャ配列（`sampler2DArray`）を走査線パリティで織り合わせる。
  各走査線群の更新周期は 1/29.97 s、フィールド全体では 1/59.94 s。
- 電子ビームのスポット径をガウス重みで表現する。
  垂直は 4 タップ、水平はバイリニア補間を利用した 2 タップで
  `[0.25, 0.5, 0.25]` 相当の重みを得る。
- 走査線表現は標本化定理上、1 走査線あたり 3 画素以上ないと表現できない。
  内部解像度から `uPixelsPerLine` を求め、2.2〜3.0 の範囲で自動的にフェードさせる。
- 蛍光体残光は前フレームを減衰させた `max` 合成で表現する。
- 走査線間の暗いすき間、画面曲率、周辺光量落ち、オーバースキャンを適用する。

### 4.6 Pass 4 — 転送（PresentFragment）

管面のハレーションを模した弱いブルームとガンマ補正を掛けてキャンバスへ出力する。

### 4.7 音声

FM 検波器の出力雑音は電力が周波数の 2 乗に比例する（三角雑音）。
これに 75µs デエンファシス（1 次 LPF、折点 2122Hz）が掛かるため、
最終的な電力スペクトルは

```
S(f) ∝ f² / (1 + (f/2122)²)
```

となる。これは **白色雑音を折点 2122Hz の 1 次ハイパスに通したもの** と等価であり、
`IIRFilterNode`（a = τ/(τ+dt)、feedforward=[a,−a]、feedback=[1,−a]）で実装する。
その後 15kHz の音声帯域制限を掛ける。

オプションでインターキャリアビート（15.734kHz）を微小レベルで加算できる。

| ID | 要件 |

## 6. アーキテクチャ

### 6.1 方針
- `main.js` は各機能の呼び出しのみを行う。
- 制御構造（ループ・状態遷移）は `AppController` に集約し、処理は下位モジュールへ委譲する。
- 依存方向は一方向とする。`main → core → pipeline/audio/ui → gl/shaders/config`
- 下位モジュールは上位モジュールを import しない（循環参照の防止）。
- 1 ファイル 1 クラス、上限 400 行。

### 6.2 ファイル構成

```
ntsc-snow/
├── index.html                      画面構成とスタイル
├── src/
│   ├── main.js                     エントリポイント（呼び出しのみ）
│   ├── core/
│   │   └── AppController.js        制御構造・状態遷移
│   ├── config/
│   │   ├── NtscConstants.js        NTSC 物理定数
│   │   └── DefaultParams.js        可変パラメータ定義（UI 自動生成用）
│   ├── gl/
│   │   ├── GLContext.js            WebGL2 コンテキスト生成

│   │   ├── RenderTarget.js         FBO 管理

```
main.js
  └─ core/AppController
       ├─ gl/GLContext

       │                          ├─ shaders/*

## 8. 既定値の設計方針

既定値は「1920×1080 以上の環境で全画面表示したときに最も実機に近く見える」ことを基準に置く。

| パラメータ | 既定値 | 理由 |
|---|---|---|
| renderScale | 1.50 | 全画面時に内部解像度が 2160×1620 程度となり、1 走査線あたり 3.3 画素を確保できる。走査線表現が成立する下限。 |
| scanline | 0.35 | 走査線間の暗いすき間がはっきり見える強さ。ウィンドウ表示など解像度が足りない場合は自動的にフェードするため、上げておいても破綻しない。 |
| spotV | 0.45 | ビームを絞ると走査線が分離し、インターレースによる 1 本おきの更新も視認できるようになる。 |
| lumaBandwidth | 4.2 MHz | NTSC の規定帯域そのもの。走査線あたりの独立成分が約 440 個となり、粒の横長具合が本来の比率になる。解像度が足りない環境では潰れて見えるため、その場合のみ 3.0〜3.6MHz へ下げる。 |

描画解像度は面積比で負荷が効くため、60fps を維持できない環境では
まず renderScale を 0.6〜0.75 へ下げること。走査線表現は自動でフェードするので
見た目が破綻することはない。

## 9. 検証方法

| 項目 | 期待値 | 確認方法 |
|---|---|---|
| 輝度分布 | レイリー分布を負変調で反転した形（暗側に裾） | 出力のヒストグラム |
| 水平相関 | 自己相関がラグ 3 前後でほぼ 0 になる | 1 走査線の自己相関 |
| 垂直相関 | 隣接走査線の相関がほぼ 0 | 走査線間の相関係数 |
| モノクロ性 | カラーキラー ON で R=G=B | 出力ピクセルの比較 |
| フィールドレート | 59.94Hz | ステータス表示のフィールド数／経過時間 |
| 音声スペクトル | 2122Hz 以下で 6dB/oct 上昇、以上で平坦、15kHz で遮断 | スペクトラムアナライザ |

CPU 参照実装（NumPy）で同一の式を計算し、統計量が一致することを確認する手順を推奨する。
1.0 版では以下の値を得ている。

```
平均 0.453 / 標準偏差 0.283
黒つぶれ率 9.8% / 高輝度(>0.8) 12.4%
水平自己相関 lag1..5 = 0.782, 0.344, 0.040, -0.029, -0.004
隣接走査線相関 = 0.042
```

## 10. 性能設計

表示パスはキャンバス全画素を走るため、負荷の大半をここが占める。1.0 版から
以下を変更し、既定条件で描画コストを約 1/4 に削減した。

| 項目 | 1.0 版 | 1.1 版 |
|---|---|---|
| 内部解像度 | 1296×972 固定 | 表示サイズに追従（描画解像度で調整可） |
| 表示パスのフェッチ数 / 画素 | 25（垂直4 × 水平3 × フィールド2 + 前フレーム1） | 9（垂直4 × 水平2 + 前フレーム1） |
| フィールド保持 | 2D テクスチャ 2 枚（毎回両方をフェッチして mix） | テクスチャ配列 1 枚（レイヤ指定で 1 フェッチ） |
| 水平スポット | 3 タップ | バイリニア補間で 2 タップ |
| Box-Muller 呼び出し | 13 回 / サンプル（FIR タップごと） | 1 回 / サンプル（Pass 0 に分離） |
| 転送パスのフェッチ数 | 常に 5 | ハレーション 0 のとき 1 |

負荷が高い場合の対処順序は次のとおり。

1. 描画解像度を 0.6〜0.75 へ下げる（効果が最も大きい。負荷は面積比で効く）
2. 管面ハレーションを 0 にする（転送パスが 1 フェッチになる）
3. ブラウザのハードウェアアクセラレーションが有効か確認する
   （パネル上部の GPU 名が SwiftShader / llvmpipe などであれば CPU 描画になっている）

ステータス行には内部解像度、実効フレームレート、および 1 フレームあたりの
JavaScript 側処理時間（CPU ms）を表示する。CPU ms が 1ms 未満であれば
ボトルネックは GPU 側のフラグメント処理である。

## 11. 既知の制約

- 同期外れによる画面のローリングや斜めの流れは再現していない。
- 実機の砂嵐に稀に混じる点火雑音（横方向の短い明線）は含まない。
- ブラウザの `requestAnimationFrame` は表示リフレッシュに同期するため、
  120Hz などの環境では 1 フレームあたりのフィールド更新数が変動する
  （`FieldScheduler` が最大 3 フィールドまで追従する）。
